# AGENTS.md

> Автоматически актуальная инструкция для агентов. При изменении ключевых файлов (ядро расчёта, экспорт, 3D, сервер, тесты) обновляй этот файл.

## Проект
Браузерный параметрический конструктор корпусной мебели. Работает как статический сайт (web/) с опциональным сервером синхронизации (server/) на Fastify + Postgres.

## Ключевые принципы
- **Ядро расчёта трогать аккуратно.** `web/model.js`, `web/model-fronts.js`, `web/export.js` — расчётное ядро. Логика меняется только осознанно.
- **Единицы измерения.** В ядре и расчётах — миллиметры. В 3D (`web/build3d.js`) — метры.
- **Сохранение совместимости.** Не ломай формат `localStorage` (`mebel-v3`, `mebel-projects`, `mebel-catalog`). Если меняешь сериализацию — учитывай миграции.
- **Русский интерфейс.** Весь UI на русском языке.
- **Без фреймворков.** Чистый ES-модульный JS, без React/Vue/Svelte. Используй существующие модули.
- **Локальный-first.** Приложение должно работать без сервера (статический хостинг).

## Структура
| Путь | Назначение |
|---|---|
| `web/` | Клиент: UI, ядро расчёта, 3D, экспорт, смета, проверка собираемости |
| `server/` | API: авторизация, проекты, версии, шаринг, каталог, синхронизация |
| `deploy/` | Caddy + Docker Compose для прода |
| `test/` | Тесты ядра (Vitest). Запуск через `./run.sh test` |

## Кухня: поля модуля
- `P.appliance` (`oven | micro | dishwasher | fridge | hood`): встраиваемая техника в первой секции; допустимые значения по типам — `TYPE_RULES[type].appliances` в `web/rules.js`, габариты ниш — `APPLIANCES` в `web/norms.js`. `normalize` очищает секцию от полок и ящиков. Прибор — `extras` для 3D и позиция фурнитуры категории `appliance`.
- `P.applianceY` (мм от пола до низа прибора) и `P.appliance2` (вторая техника, встаёт на первую) — только у `ktall` с духовкой или СВЧ (`TYPE_RULES.ktall.stack`). Вытяжка над варочной панелью проверяется в проекте (`hoodWarnings` в `web/worktop.js`, расстояние 650–850 мм).
- `P.cornerKit` (`blind | carousel | magic`) у `kcorner`: угловой механизм вместо глухого угла (`web/model-corner.js`).
- Вырез столешницы может лежать на любой плите: `run` (0 — первая, 1 и 2 — повёрнутые и дальняя); у плиты в `back` направление к стене.
- Вырезы столешницы `sink` и `hob` дают покупные приборы (`worktopFixtures` в `web/worktop.js`): 3D, план, список покупок; цвет — `countertop.color`.
- Все новые значения таких моделей перечислены в `web/verify.js` как не подтверждённые источниками.

## Экспорт и форматы
- **CSV:** `;`, UTF-8 BOM
- **DXF:** R12, cp1251, контур детали — замкнутый POLYLINE (дуги через bulge). Слои: `D{Ø}_H{глуб}_{A|B}`, `_SKV`, `_TORETS`, `KROMKA_*`, `PAZ_*`, `VYREZ`, `FREZA_RAMKA_*`, `OKNO_SKV`, `FALTS_*`
- **3D:** three.js 0.184, модули через import map в `web/index.html`

## Тестирование
- `./run.sh test` — тесты ядра (Vitest); при диагностике через прокси RTK запускай `rtk proxy npx vitest run`
- `./run.sh servertest` — тесты сервера с временным Postgres
- `./run.sh full` — полная проверка

При изменениях в `web/model*.js`, `web/export.js`, `web/rules.js`, `web/check.js` обязательно прогнать `./run.sh test`.

## Сервер и синхронизация
- API: `/api/*`, авторизация через httpOnly cookie
- Local-first: всё работает из localStorage
- Синхронизация через `web/sync.js`, конфликты разрешаются по версии
- Просмотр по ссылке: `view.html`, `production.html?share=...`

## Релиз и кеш
- Сервис-воркер работает cache-first: при изменении файлов в `web/` увеличивай версию командой `./run.sh bump`; новые модули добавляй в список `ASSETS` (тест `test/service-worker.test.js` проверяет состав).
- В проекте есть `P.schema` и `migrate()` в `web/rules.js`: при несовместимом изменении формата проекта поднимай `SCHEMA` и добавляй функцию в `MIGRATIONS`.
