# Конструктор корпусной мебели — передача в Claude Code

## Что это
Браузерный параметрический конструктор корпусной мебели (шкаф, стеллаж, тумба, комод, ТВ-тумба) с 3D-просмотром и выгрузкой для распилочного цеха. Работает без сервера: только статические HTML и JS, three.js 0.184.

**Это рабочий код, а не макет.** Его нужно взять за основу и развивать, а не переписывать с нуля. Пересборка на фреймворк (React, Vue) допустима, но расчётное ядро (`model.js`, `model-fronts.js`, `export.js`) нужно сохранить без изменения логики.

## Структура репозитория
- `web/` — клиент (всё, что описано ниже в таблице файлов; пути в таблице даны относительно `web/`);
- `server/` — API (Node 22, Fastify, Postgres);
- `deploy/` — Caddy (шлюз), Docker Compose для разработки и прода;
- `run.sh` — запуск, проверка, сборка (`./run.sh dev` поднимает весь сервис).

## Запуск
Только клиент (без аккаунтов, всё в localStorage): `./run.sh serve` или любой статический сервер для папки `web/`, потому что ES-модули не работают через `file://`:
```
npx serve .        # или: python3 -m http.server 8080
```
Весь сервис с аккаунтами: `./run.sh dev` → http://localhost:8088 (письма — http://localhost:8025, Mailpit). Если API недоступен (статический хостинг), кнопка «Войти» скрывается и приложение остаётся локальным.

## Модель данных
- Параметры `P`: габариты (`height`, `depth`, `thickness`), `base`/`plinth`, `topType` (`inset`/`overlay`)/`topOverhang`, `backType` (`groove`/`overlay`/`none`), `doorType` (`hinged`/`sliding`), фасады, ручки, кромка (`edgeFront`, `edgeHidden`), цвета, вид (`open`, `hideDoors`, `showHoles`).
- Вырезы: `P.cutouts[]` = `{ part, sec, kind: 'hole' | 'notch', w, h, r, u, v, corner }`. `hole` — прямоугольный вырез со скруглением, центр (u, v) от Ш1 и Д1; `notch` — выемка в углу. В детали — `p.cutouts` (координаты прямоугольника в системе детали). Проверка: не ближе 10 мм к краю, не задевают присадку, не пересекаются. Попадают в задание (чертёж и таблица), CSV, DXF (слой `VYREZ`) и 3D.
- Фрезеровка фасадов: у фасада `p.mill` (рамочный: окно и утопление филёнки; под стекло: сквозное окно и четверть). Параметры в справочнике (`catalog.milling`: ширина рамки, глубина, радиус, заход стекла, фаска и углы стекла). DXF: слои `FREZA_RAMKA_<глубина>`, `OKNO_SKV`, `FALTS_<глубина>_B`.
- Пределы: высота ящика не меньше 100 мм (короб 70 мм + 20 мм от низа); основание не больше «высота − 200» мм; зона деления отключается, если внутренняя высота меньше 400 мм. Ручка-скоба должна лежать на фасаде (горизонтальная — `межосевое + 46` мм, вертикальная — `+ 100` мм), иначе предупреждение и автоисправление.
- Фурнитура: `P.slide` (`ball` | `ballSoft` | `hidden` | `roller`: меняет ширину короба, длины, ход, крепление), `P.hinge` (`soft` | `plain` | `wide` 165°), `P.push` (push-to-open: только без ручек, петли без доводчика), `P.wallFix` (анкерные уголки), `P.fittings` (`{ 'категория[:вариант]': id модели }`).
- В `spec`: у каждой детали и extra поле `asm` (этап сборки, порядок — `STAGES` в `model.js`), `spec.hwx` — фурнитура с категорией и этапом (`spec.hw` прежнего формата сохранён).
- `P.joint`: крепёж корпуса `confirmat` | `minifix` (штифт Ø5×12 + стяжка Ø15×13 + торец Ø8×34 + шкант) | `dowel` (шканты Ø8, два на точку).
- `P.sections[]`: `{ width, door: none|left|right|double|flapDown|flapUp, split, frontStyle, items[], zone }`.
- `zone`: `{ pos: bottom|top, h, split, left[], right[] }` — деление секции по высоте: стационарная полка-граница, полуперегородка и две колонки со своими полками (`shelf|fixed|glass`, `y` от низа зоны). Основные элементы, целиком попавшие в зону, `normalize()` удаляет.
- `items[]`: `{ type: shelf|fixed|glass|rod|drawer, y /* мм от дна секции */, h /* для ящика */ }`.
- Общая ширина изделия = сумма ширин секций + (n+1)·толщина.
- Системы координат деталей, сторон (пластей) и торцов описаны в шапке `model.js`. Их нельзя менять без синхронной правки `build3d.js`, `export.js` и `production.html`.

## Конструктивные правила (реализованы)
- Боковины на всю высоту; дно и крышка (вариант «между боковинами») ставятся между боковин на конфирматы 7×50: Ø7 насквозь в пласти, Ø5×50 в торце. Точки крепления в 50 мм от краёв, третья — посередине при глубине больше 450 мм.
- Съёмные полки ставятся на полкодержатели Ø5×12, 3 позиции с шагом 32 мм, в 37 мм от переднего и заднего края.
- Петли:
  - чашка Ø35×13 в 21,5 мм от края двери, первая и последняя в 100 мм от торцов;
  - количество по высоте двери: до 900 мм — 2, до 1600 — 3, до 2100 — 4, выше — 5;
  - ответная планка: 2 отверстия Ø5×12 (±16 мм) в 37 мм от переднего края;
  - на перегородке ставятся полунакладные петли.
- Ящики:
  - короб из 16 мм; ширина = проём − 26 мм;
  - направляющие шариковые, длина кратна 50 мм;
  - за распашной дверью фасад ящика утоплен на 25 мм.
- Пильный размер = чистовой − кромка толщиной от 1 мм.
- Если полки соседних секций стоят на одной высоте, точки крепления у общей перегородки сдвигаются на 40 мм (отверстия с двух сторон не совпадают).
- Раскрой гильотинный: свободные прямоугольники, пропил и обпил из справочника, текстурные детали не поворачиваются, перебираются четыре порядка деталей. Деловые остатки и длина реза возвращаются в `nest()`.
- Отмена и повтор (Ctrl/⌘+Z, Ctrl/⌘+Shift+Z): одна правка или одно перетаскивание ползунка — один шаг; параметры вида не записываются.
- Интерфейс: верхняя панель (проекты, название, тип, габариты, отмена/повтор, индикатор сохранения, «Задание на распил», меню «Экспорт», справочник), слева вкладки «Секции / Параметры», плашка «Вид» поверх 3D. Тип изделия выбирается только при создании проекта на экране «Проекты» (карточки с миниатюрами, поиск, дублирование, импорт/экспорт); первый запуск сразу открывает создание проекта.
- Мобильная версия (до 760 px): панель выезжает снизу в трёх положениях, вкладки «Секции / Параметры», экспорт — в меню шапки, элементы от 44 px.

## Физика и опоры (реализовано)
- Цоколь — рама: передний, задний, боковые и под каждой перегородкой; боковины стоят на раме. Задняя часть корпуса не висит.
- Полки лежат на полкодержателях (видны в 3D), петли — с планкой, чашкой и рычагом, откидные фасады — со стабилизаторами или газлифтами, ящики — на трёхсекционных направляющих.
- Ось двери — на лицевой кромке, угол 90°: дверь не заходит в соседнюю. Петли сдвигаются от полок.
- Ящик за распашной дверью стоит на проставках из ЛДСП (короб уже на 2 толщины), фасад вплотную к коробу. Режим секции `drawerFronts`: `inset` или `overlay` (накладные ящики сами служат фасадом, дверь выше).
- Купе: верхний рельс с тремя бортиками, нижний — с гребнями, полотна висят на каретках.
- Пол в 3D всегда на y = 0.
- Встроенные ящики (`idrawer`): всегда за дверью секции, на проставках, без ручки (выемка под пальцы). Ящики за дверью и за купе ручек не имеют — ручка прошла бы сквозь дверь.
- Ручка-профиль не длиннее фасада и целиком лежит на нём; горизонтальные скобы на двойных дверях не встречаются над зазором.
- «Подстраивать под размеры» (`P.fit`, `P.fitMode`): при смене высоты, толщины и основания полки, штанги и ящики пересчитываются пропорционально или раскладываются заново поровну (`fitSections` в `rules.js`). «Распределить имеющиеся» делает то же вручную.
- Подсказки «?» у параметров, схема секции, кнопка «Отменить» для шаблонов, автозаполнения и автоисправления.
- Предупреждения: если при полном открытии деталь упирается, интерфейс пишет, во что именно.
- Параметры по типу: шкаф — штанги, антресоль, карниз, купе; стеллаж — только полки; тумба/комод/ТВ-тумба — ограниченные наборы дверей и элементов. Недопустимое сбрасывает `normalize()`.

## Известные ограничения
- Справочник: `version` схемы (`CATALOG_VERSION`): при выходе новых моделей по умолчанию они дописываются в сохранённый справочник по `id`. `sanitizeCatalog` приводит любой справочник (из хранилища, с сервера, по чужой ссылке, из импорта) к ожидаемой форме.
- Радиус внутреннего угла выемки в 3D не показывается (в чертеже и DXF есть). Вырезы только прямоугольные (с радиусом углов), круглых нет.
- Скрытые направляющие (`hidden`): зазор короба 21 мм на сторону принят по типичным данным производителей, сверьте с паспортом выбранной модели. Петли 165° у соседних дверей упираются друг в друга: предупреждения покажут.
- Артикулы в справочнике пустые (заполняются своими), цены моделей фурнитуры примерные.
- В колонках зоны деления допустимы только полки; ящики и штанги в колонках не поддерживаются.
- Раскрой — эвристика, а не оптимум; остатки со склада и многоэтапный раскрой под конкретную пилу не учитываются. Для серийного производства лучше «Базис-Раскрой».
- Форматы ЧПУ: только DXF; MPR/BPP/XXL не реализованы.
- Цены в справочнике — примерные, замените на свои.
- Нужна сверка присадки с конкретной фурнитурой: Blum, Hettich, Boyard и т. п.

## Сервис: аккаунты, хранение, синхронизация
**Схема:** браузер → Caddy (`deploy/Caddyfile`: TLS, статика из `web/`, `/api/*` → api) → Fastify (`server/`) → Postgres. Миграции — `server/migrations/*.sql`, применяются при старте.

**Local-first.** Интерфейс по-прежнему работает от localStorage и офлайн. `web/sync.js` сверяет состояние с сервером: что изменилось, определяется по хешу содержимого (параметры вида `open/hideDoors/showHoles` правкой не считаются), удаление — по исчезновению проекта.
- Первый вход: проекты устройства загружаются в аккаунт. Выход: оставить проекты на устройстве или стереть.
- Конфликт проекта: основной становится серверная версия, локальная остаётся копией «Название (конфликт ДД.ММ)». Удалён на сервере, а правился здесь — заводится как новый проект.
- Справочник: первый контакт — побеждает сервер (локальный — в `mebel-catalog-backup`); при правках на обоих устройствах — тот, кто синхронизируется позже.
- Хуки записи: `projects.js` (`hooks.onSave`), `catalog.js` (`catalogHooks.onSave`); формат хранения не менялся.

**Авторизация:** email + пароль (argon2id), сессия — httpOnly-cookie SameSite=Lax с непрозрачным токеном (в БД только sha256), проверка `Origin` на изменяющих запросах, rate limit (жёстче на `/auth/*`). Почта подтверждается ссылкой; сброс пароля и «Ссылка для просмотра» требуют подтверждённой почты.

**API** (`/api`): `auth/{register,login,logout,me,verify,resend-verify,forgot,reset}`; `projects` (`GET ?since=`, `GET|PUT|DELETE /:id`, PUT с `baseVersion` → 409 при конфликте), `projects/:id/thumb`, `projects/:id/versions[/:vid[/restore]]` (снимок не чаще раза в 10 минут, хранится 50), `projects/:id/share` (POST/DELETE), публичный `share/:token`, `catalog` (GET/PUT), `health`. Проект проверяется сервером тем же ядром (`web/rules.js` → `normalize`, `web/model.js` → `buildSpec`).

**Просмотр по ссылке:** `view.html?t=токен` (3D, только чтение), `production.html?share=токен` — задание и КП с ценами из справочника владельца.

**Тесты сервера одной командой:** `./run.sh servertest` (сам поднимает и убирает Postgres в Docker); `./run.sh full` — всё вместе с тестами ядра.

**Что проверяют тесты ядра:** снимок `buildSpec` для пресетов, `checkBuild` на пресетах и случайных проектах, расширенный перебор (400 проектов с крайними значениями: выгрузки без NaN, а если расчёт не предупредил о проблеме, проверка не должна находить ошибок), список покупок и полнота крепежа, инструкция, вырезы и фрезеровка, структура DXF, страница задания и защита от подмены через справочник по ссылке.

**Тесты (вручную):** `docker run -d --name mebel-pg-test -p 55432:5432 -e POSTGRES_PASSWORD=test -e POSTGRES_DB=mebel_test postgres:16-alpine`, затем `cd server && npm test` (API и синхронизация против настоящей БД; `TEST_DATABASE_URL` переопределяет адрес).

**Прод:** `cd deploy && cp .env.example .env` (домен, пароль БД, SMTP) → `docker compose up -d --build`. Контейнер `backup` делает суточный `pg_dump`, хранит 14 дней.

**Ограничения:** версии и ссылки доступны только для синхронизированных проектов; задание по ссылке показывает расчёт без снимка 3D в КП; смена email и удаление аккаунта не реализованы.
